\section{Background} \label{sec:background}
The term prompt injection attack does not describe a specific attack against an LLM but rather a family or group of related attacks with similar modes of action and threat models.
In this section, we introduce some general definitions that can be applied to any prompt injection attack.
The definitions are mainly based on the formalization of prompt injection attacks by \liu~\cite{}.
We will go into more details on specific prompt injection approaches in the following section.

\subsection{LLM Prompting} \label{sec:llm_prompting}

    \label{fig:llm_application}

The basic functionality of any LLM-integrated application is to utilize an LLM $f$ in order to process external data on behalf of the user.
To do so, the LLM is provided with a prompt $\textbf{p}$ consisting of textual task instructions $\textbf{s}^t$ and external data $\textbf{x}^t$~\cite{}.
This data is often, but not exclusively, text-based and can incorporate a wide range of information types like web pages, source code, and different document types.
While the simplest way to combine instructions and data is through simple concatenation in the form of prefix prompts, there are other possible approaches.
In general, the data can be joined with the instructions through slot-filling with an arbitrary number and distribution of slots within the instructions.
We denote the arbitrary combination of instruction and data into a prompt with the notation shown in~\cref{eq:prompt_constr}.
\begin{equation}
    \textbf{p} = \textbf{s}^t \circ \textbf{x}^t
    \label{eq:prompt_constr}
\end{equation}
We use the arbitrary combination operator $\circ$ in rather than the more specific string concatenation operator $\oplus$ used by \liu to ensure the notation applies to all presented prompt injection approaches~\cite{}.
The task instructions $\textbf{s}^t$ themselves can consist of parts originating from the user and the application.
Instructions from the application $\textbf{s}^a$, often referred to as the system prompt, usually define guard rails or steer the model towards a specific task that is intended by the application.
User instructions $\textbf{s}^u$ might contain a more specific task description, directly provided information, or in-context learning examples.
Analogously to the construction of the prompt, user and application instructions can be combined arbitrarily: $\textbf{s}^t = \textbf{s}^a \circ \textbf{s}^u$~\cite{}.
\\

The prompt $\textbf{p}$ is processed by an application's internal LLM and converted into a response $\textbf{r} = f(\textbf{p})$ that is returned to the user.
\Cref{fig:llm_application} depicts the connections between the application, LLM, user, and external data.
Such real-world applications include the GUIs of popular LLMs like ChatGPT, Gemini, and Claude, as well as third-party services and even the incorporation of LLMs in application processes without the user being aware of their use.
The fundamental construction of prompts which we introduce in this section is used by all LLM-integrated applications and serves as the basis of prompt injection attacks.

\subsection{Threat Model} \label{sec:threat_model}
Since prompt injection attacks are a cyber security threat in the context of LLMs, their formal definition needs to be associated with a threat model.
In the following we introduce a general attacker goal and attacker capability that apply to all prompt injection attacks as defined in~\cref{sec:prompt_inj_def}.
We point out any additions or deviations from this general threat model in the sections on the individual approaches.\\

\textbf{Attacker Goal~\cite{}:}
In any prompt injection attack, the attackers main goal is to manipulate the LLM into outputting an attacker-chosen response $\tilde{\textbf{r}}$ which differs from the models non-manipulated output $\textbf{r}$ for the same task.
In general, the chosen response is arbitrary.
However, in many cases additional constraints apply to the response $\tilde{\textbf{r}}$ according to the attacks intention.
For example the attacker might chose the response $\tilde{\textbf{r}}$ to be from the same domain or distribution as $\textbf{r}$.
The attacker goal is one of the main distinguishing factors between different prompt injection approaches.
Concrete attacker goals are as diverse as the applications and tasks of the attacked LLMs.
Therefor the definition of the overall attacker goal in an arbitrary prompt injection attack needs to be kept general.\\

\textbf{Attacker Capabilities~\cite{}:}
The attacker's most important capability is the manipulation of the external data $\textbf{x}^t$ used in the prompt construction.
This manipulation is, however, not arbitrary but limited to the injection of additional data, as the name prompt injection attack implies.
This explicitly excludes the ability of altering the data that is submitted to the prompt construction by the user or the application.
Though it does not principally limit the injected data in length or type.\\

Many prompt injection attacks also assume that the attacker can acquire knowledge about the attacked application.
Examples for such knowledge include the exact model of the attacked LLM, the system prompt $\textbf{s}^a$, or details on the data processing pipeline like pre-processing or filters applied to either input or output.
However, such additional attacker knowledge cannot be assumed by every prompt injection attack.
For example prompt leaking attacks, that aim at manipulating the model into outputting the system prompt, typically do not assume that the attacker has any prior knowledge about the system prompt.

\subsection{Prompt Injection Attacks} \label{sec:prompt_inj_def}
Based on the formal definition of LLM-integrated applications in~\cref{sec:llm_prompting}, prompt injection attacks can be defined.
The basic threat model of any kind of prompt injection attack includes an attacker pursuing the goal of changing the LLM's output from fulfilling the target task to fulfilling an attacker-defined injected task instead.
This is achieved by manipulating the external data that is processed by the application~\cite{}.
Intuitively, prompt injection attacks can be understood as an attacker exploiting the fact that the external data processed by LLM-integrated applications is often prone to manipulation.\\

Formally, the attacker alters the external target data $\textbf{x}^t$ to a compromised data set $\tilde{\textbf{x}}$~\cite{}.
He can do so not only by involving injected data $\textbf{x}^e$ but also injected instructions $\textbf{s}^e$.
Since there are diverse ways of altering the target data $\textbf{x}^t$, we denote the construction of the compromised data set through the execution of an attack function $\mathpzc{A}$ as shown in~\cref{eq:compr_data}.
\begin{equation}
    \tilde{\textbf{x}} = \mathpzc{A}(\textbf{x}^t, \textbf{x}^e, \textbf{s}^e)~\cite{}
    \label{eq:compr_data}
\end{equation}
In the case of an attack, the compromised external data $\tilde{\textbf{x}}$ is used to construct a compromised prompt $\tilde{\textbf{p}}$ analogously to~\cref{eq:prompt_constr}:
\begin{equation}
    \tilde{\textbf{p}} = \textbf{s}^t \circ \tilde{\textbf{x}},
    \label{eq:compr_prompt_constr}
\end{equation}
which leads to a changed model response $\tilde{\textbf{r}} = f(\tilde{\textbf{p}})$. Considering the compromised data $\tilde{\textbf{x}}$ contains the injected data $\textbf{x}^e$ and more importantly, the injected instructions $\textbf{s}^e$, shows how the attacker takes influence on the LLM.
This demonstrates that prompt injection attacks are fundamentally based on the mixing of instructions and data in the construction of prompts.
We further discuss this fundamental problem in~\cref{add_later}\\

The general definition of prompt injection attacks by \liu only describes the fundamental characteristic shared amongst all prompt injection variants.
Two main parameters create the variety of prompt injection attacks found in the literature.
One parameter is the injected task defined by the attacker, the spectrum of which can be as broad as the target tasks of various applications.
A prominent example is the leaking of the system prompt by the LLM~\cite{}.
The other parameter is the definition of the attack function $\mathpzc{A}$.
Just like with the construction of prompts shown in~\cref{eq:prompt_constr}, the naive approach is to concatenate the instruction data with the components injected by the attacker.
However, much more complex approaches can be used, which can be adjusted to the attacked application's LLM, target task, and the injected task~\cite{}.
By presenting and discussing several case studies in the following chapters, we provide an overview of the variety of prompt injection techniques with different injected tasks and attack approaches.

\subsection{Prompt Injection Approaches}
We divide the prompt injection approaches that we discuss in the following chapters into two main groups.
The first group contains approaches based on \textbf{word-level attack prompt construction}.
These approaches try to achieve the attacker goal by varying the phrasing of the injected instructions $\textbf{s}^e$ and are therefor closely related to general guidelines for effective prompt formulation.
We present a manual approach following this notion in~\cref{sec:manual_prompts} and one that automates some of the formulation optimization in~\cref{add_later}.\\

The second group of prompt injection approaches is based on \textbf{token-level attack prompt optimization}.
These approaches do not rephrase the injected instructions but algorithmically identify and evaluate the change of individual tokens in the injected data.
Because such approaches can define the prompt injection attack as an optimization problem with a related loss function, they are able to use gradient-based optimization techniques to find optimal attack prompts.
We present two prompt injection attacks from this group with different optimization techniques in~\cref{add_later}.
